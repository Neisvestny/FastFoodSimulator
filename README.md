# Fast Food Simulator

Кроссплатформенный симулятор ресторана быстрого питания на C# / .NET 10 + Avalonia UI.
Четыре участника процесса — клиент, кассир, повар и сервер выдачи — работают как
независимые асинхронные задачи. Интерфейс построен по MVVM, настройки и ход симуляции
управляет пользователь.

## Требования

- .NET SDK 10

## Запуск

```bash
dotnet run
```

## Управление

Задайте четыре интервала в миллисекундах (целые положительные числа):

- **Приход клиентов** — как часто появляются новые клиенты;
- **Приём заказа** — время обслуживания одного клиента кассиром;
- **Приготовление** — время приготовления одного заказа поваром;
- **Выдача** — пауза сервера перед вызовом номера.

Задайте численность персонала (от 1 до 5 на роль): кассиры, повара и серверы выдачи.
При вводе аватары на сцене обновляются сразу, каждый сотрудник различим по номеру.
Панели состояния показывают заказы всех занятых сотрудников роли.

При некорректном вводе под полем появляется сообщение об ошибке. Кнопка «Старт»
запускает симуляцию, «Стоп» останавливает её и сбрасывает очереди, счётчики и сцену.
На время работы поля настроек блокируются.

## Интерфейс

- **Панели состояния** — линия клиентов (счётчик), приём заказов (текущий номер),
  кухня (номер в приготовлении, список ожидающих тикетов и счётчик), выдача
  (номер, доступный к выдаче, и число клиентов в очереди ожидания).
- **Графическая сцена** — кружки клиентов перемещаются по маршруту
  «вход → линия заказов → касса → линия ожидания → стойка выдачи → выход».
  Тикеты движутся по кухонной карусели, меняют цвет при готовке и на стойке выдачи.
- **Журнал событий** — хронология хода симуляции.

## Синхронизация

`OrderTicket` содержит два `TaskCompletionSource`:

| Точка синхронизации | Кто ждёт | Кто резолвит | Когда |
|---|---|---|---|
| `OrderReadyForServer` | Сервер | Повар | После завершения приготовления |
| `OrderReadyForCustomer` | Клиент | Сервер | После вызова номера на стойке выдачи |

Каждый участник работает как отдельная асинхронная задача (`async/await` +
`CancellationToken`). Очереди между этапами — `SimQueue<T>` на `SemaphoreSlim`.
Симуляционные библиотеки не используются.
